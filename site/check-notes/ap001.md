## What it finds

A key written in the files where an agent keeps what you did: prompt history, saved transcripts,
the paste cache, file edit backups and chat databases. Examples are `~/.claude/history.jsonl`,
`~/.codex/sessions/` and the chat database of an editor.

Keys are found by pattern: Anthropic, OpenAI, GitHub, AWS, Stripe, Slack and Google formats, plus
a "secret-looking name = random-looking value" rule. Each print shows the key masked, for example
`sk-a…(len 105)`.

## Why it matters

When you paste a key into a chat, the agent saves it as plain text in your home folder. Any
program you run can read that folder. Old history is easy to forget and is rarely cleaned up.

## How to fix

1. Rotate the key with its provider. Revoke the old one and make a new one. Treat the old key as
   public.
2. Delete or redact the history file. agentprint never edits history for you.
3. Next time, put keys in an environment variable and do not paste them into a chat.

## Limits

- Pattern-based only. A key in an odd format can be missed.
- Obvious placeholders such as `ghp_xxxx...` or `your-api-key` are not reported. They are still
  masked in anything agentprint prints.
- A key hidden on purpose is found too: cut by invisible characters (such as zero-width
  spaces), split into quoted pieces joined with `+`, `.` or `..` or written side by side, cut
  by an empty quoted string (`abc""def`, `abc''def`), folded over lines with a trailing
  backslash or in a YAML `|` or `>` block, or base64-encoded. Base64 shorter than 40 characters
  counts only when it decodes to exactly one whole key, such as a lone AWS key ID.
  Inside a JSON string (a transcript line) the same tricks are found, except the cases listed
  under "Still missed". The print says how, for example `sk-a…(len 105) (hidden: split string)`.
- `agentprint fix` cannot mask a hidden key, because its characters are not stored together.
  Removing it is left to you.
- When a key's first part is a whole key on its own, the print shows that plain part; the
  hidden rest is not reported separately.
- When only the first part of a hidden key is found, `fix` masks that part and the rest stays
  in the file; rotate the key and remove the rest by hand.
- Still missed:
  - a key put together while a program runs (from variables, a join, string formatting or a
    decode call), or a key inside an arbitrary script or binary file;
  - pieces in backtick template literals;
  - inside a JSON string: pieces joined by `.` or `..` without a space on each side
    (`"a"."b"`), and pieces split over lines;
  - an empty quoted string with anything but a letter, digit, `_`, `-` or `.` right before or
    after it;
  - base64 shorter than 24 characters, and base64 of 24 to 39 characters that holds anything
    but one whole key (`k=` and a key, say);
  - URL-safe base64, base64 of mostly non-ASCII text, base64 wrapped over several lines, and
    text encoded twice;
  - a YAML block header inside a JSON string written with extra spaces or a comment after the
    `|` or `>`;
  - a hidden PyPI or 1Password service account token longer than about 600 characters (a token
    is read hidden only when both halves around the hiding spot fit in 320 characters);
  - hidden keys past the per-file limits: 10,000 joins of each kind and 1 MiB of joined text
    per 8 MiB of a file, 256 base64 blobs (64 KiB each) and 4,096 escaped JSON strings per file.
- agentprint never uses the key, so it cannot tell you if it still works.
- Credential stores such as `~/.codex/auth.json` are never read. See [AP008](/agentprint/checks/ap008/).
