summary: Agent history, settings or a key store can be read by other users on this machine (macOS, Linux and Windows).
runs_in: [scan]
severity_note: high for key stores

## What it finds

An agent file in your home folder, or a personal or credential file inside a project, that other
users on the same machine can read. On macOS and Linux, a file counts as readable when its mode
allows it and every folder above it lets that user in. Symlinks are followed.

On Windows there are no modes: agentprint reads the file's access list (its ACL). The file counts
as readable when the list lets any account or group read its contents, except you, SYSTEM,
Administrators, Backup Operators, LOCAL SERVICE, NETWORK SERVICE, CREATOR OWNER, Windows services
and apps running for you. So Everyone, Users, Authenticated Users, another account, or a group
agentprint has no name for all count.

A credential store, such as `~/.codex/auth.json` or `~/.hermes/.env`, is a high print. Other
files are medium.

## Why it matters

History, settings and key stores often hold keys and private conversations. Some agents create
them readable by everyone: a June 2026 Hermes Agent advisory (CVE-2026-53870) covers exactly that.

## How to fix

Run one command, for example `chmod -R go-rwx ~/.hermes`. This covers files created later too.
For a single file, run `chmod go-rwx <file>`. The fix uses `go-rwx` and not `600` so hook scripts
keep their execute bit. If a path has unusual characters, the print gives a plain sentence
instead of a command.

On Windows the print gives the `icacls` command for the file, with your account's SID filled in:
`icacls "<file>" /inheritance:r /grant:r *<your SID>:F *S-1-5-18:F *S-1-5-32-544:F`. It turns off
what the file inherits from its folder, gives you, SYSTEM and Administrators full control, and
so removes the other users that could read it through the folder. If the file names another
account itself, the command ends with `/remove:g` and that account's SID. A path with `$`, a
backtick, `%` or `!` is put in single quotes, for PowerShell. For an agent folder with several
such files, the print says to run `agentprint fix --only AP008`, which runs the same command on
each file and can undo it. There is no `chmod` on Windows.

## Limits

- On Windows, the folders above the file don't count: by default every account may pass through
  a folder to a file it is allowed to read. A Deny entry counts only for the same account or
  group, or for Everyone. Groups an account belongs to are not looked up.
- On Windows, a file is not checked when its access list can't be read, when it has conditional
  or other entries agentprint does not read, or when its drive keeps no permissions (FAT,
  exFAT, some network drives). The sweep says so in a "not checked" line that names the file.
- On Windows, a file made by a program run as administrator is owned by Administrators. It is
  checked when agentprint runs as administrator too; otherwise it is named as not checked.
- A file owned by another account is not reported: it is theirs to fix.
- Shared project config such as `.mcp.json` is not checked: git does not record read
  permissions, and teammates are meant to read it.
- Credential stores are only checked for who can read them. Their contents are never read.
